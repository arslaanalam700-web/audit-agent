# Spearmint audit agent handover

This is the operating guide for the website and SEO audit system in this repository. The private GitHub remote is https://github.com/Krux-ai-official/spearmint-audit-agent. The product is version 2.0.0.

Spearmint is a web studio in India. The system audits a prospect or client site, writes the findings down with evidence, and turns the verified findings into a pitch and a fix list. It does not email the client and it does not edit the client's website unless a person has approved a WordPress change.

## Two layers

The audit engine is Python and does not call a model. It crawls, renders when asked, runs the checks, and stores every number. Scores, counts, and timings in a report come from this layer.

Hermes agents interpret that data. They judge content, verify findings, and write fixes. They do not pass the crawl to each other. They share the SQLite database and send only small JSON tasks over the Agent2Agent protocol (A2A).

Website text is untrusted. A page can contain instructions aimed at the model. Specialists have no terminal, browser, or file-write tools. They can read the engine and submit findings.

## Agent roster

Each agent is a Hermes profile. Profiles are generated by `python hermes/build_profiles.py`. On Windows, `hermes/bootstrap.ps1` copies them to `%LOCALAPPDATA%\hermes\profiles`. Each profile runs its own gateway because each one binds its own A2A port. A shared Hermes gateway cannot host all of those listeners.

| Profile | Port | Model on OpenRouter | Job |
|---|---|---|---|
| lead | 9900 | `nousresearch/hermes-4-405b` | Start the audit, fan out, collect QA and the fix plan, queue internal delivery |
| technical | 9901 | `nousresearch/hermes-4.3-36b` | Crawl, indexability, redirects, canonicals, hreflang, schema, AI-crawler access |
| content | 9902 | `nousresearch/hermes-4.3-36b` | Titles, metas, headings, thin and duplicate copy, replacement text |
| performance | 9903 | `nousresearch/hermes-4.3-36b` | Lighthouse and CrUX, page weight, caching, per template |
| ux | 9904 | `google/gemini-2.5-flash` | axe-core, mobile render, conversion elements. This model can look at images |
| security | 9905 | `nousresearch/hermes-4.3-36b` | TLS, security headers, cookies, SPF, DMARC. Passive only |
| offpage | 9906 | `nousresearch/hermes-4.3-36b` | Backlinks and client analytics when those keys exist |
| qa | 9907 | `nousresearch/hermes-4-70b` | Reject findings that lack evidence. May challenge a specialist for at most two turns |
| fixer | 9908 | `nousresearch/hermes-4-70b` | Tickets, report, pitch |
| wpfixer | 9909 | `nousresearch/hermes-4.3-36b` | Optional. Proposes WordPress title edits and applies them only after approval |

The lead calls technical, content, performance, ux, security, and offpage together with `a2a_orchestrate(capability="audit_specialist", mode="all")`. QA, the fixer, and the WordPress fixer are not in that fan-out. QA calls the specialists itself. Reply timeout is 1800 seconds. Ping-pong turns are capped at 5.

Tool allow-lists are in each profile's `config.yaml`. The lead and QA also get the A2A toolset. Everyone else gets skills, memory, and the audit MCP server only. The lead's public agent card advertises that same restricted set.

## How one audit runs

1. A person, a webhook, or a cron job asks the lead for a URL.
2. The lead calls `start_audit`, then `wait_for_audit`. The wait blocks for up to 10 minutes per call so the model is not polling.
3. The engine crawls, checks, and writes findings with status `verified` and evidence attached. The score is computed here.
4. The lead sends one small `AuditTask` JSON object to every `audit_specialist`.
5. Specialists read pages and may call deep checks. New findings go through `submit_findings`. A finding without evidence is rejected.
6. QA re-checks agent findings with `update_finding`. Engine scores stay as the engine wrote them.
7. The fixer calls `create_fix_tickets` and `build_report`.
8. The lead calls `queue_delivery`. That writes `data/outbox/<id>.json` with status `pending_review`. `approve_delivery` marks it approved. It does not send email.

Webhook route, on the lead only: `POST http://127.0.0.1:8644/webhooks/audit`. The body should include `url`, `client_name`, and `email`. The route requires the webhook secret. An unsigned request returns 401. The prompt tells the agent not to email the address in the form.

Chat, once a messaging platform is connected: `/website-audit`. Slack and WhatsApp are not connected in this handover. Their tool lists are already restricted, so connecting them later does not grant a shell. Tokens for those platforms are added with `hermes gateway setup`.

Monthly and weekly re-audits are documented in `hermes/cron.snippet.yaml`. Create them with `hermes -p lead cron create`. They log the result and queue delivery. They do not email the client.

## Run it on this PC

Requirements: Python 3.11 or newer, and the Hermes Agent CLI. On the machine used to build this, Hermes is installed at `%LOCALAPPDATA%\hermes` and the command is `%LOCALAPPDATA%\hermes\bin\hermes.exe`. The official installer is `https://hermes-agent.nousresearch.com/install.ps1`. Its setup wizard needs an interactive console. `hermes/bootstrap.ps1` skips that wizard and writes the profiles directly.

```powershell
cd audit-agent
pip install -r requirements.txt
python -m engine.site_audit https://example.com --client-name "Acme" --no-pagespeed --no-open
```

Useful flags: `--max-pages` (CLI default 200, service default 2000, hard cap 2000), `--render`, `--axe`, `--check-external`, `--psi-samples`, `--ai`, `--db`.

The MCP server reads `audit-agent/.env` when that file exists. A local `.env` is created by `python hermes/build_profiles.py --install` and is gitignored.

```powershell
python -m mcp_server.server
```

Health check without a token: `GET http://127.0.0.1:8800/health`. Every `/mcp` call needs `Authorization: Bearer <AUDIT_MCP_TOKEN>`.

Then start a gateway per profile, after `OPENROUTER_API_KEY` is in each profile `.env`:

```powershell
hermes -p lead gateway start
hermes -p technical gateway start
```

Repeat for content, performance, ux, security, offpage, qa, fixer, and wpfixer. The lead card is `http://127.0.0.1:9900/.well-known/agent-card.json`.

`python hermes/build_profiles.py` rewrites the files in `hermes/profiles/`. `python hermes/build_profiles.py --install` also copies them into the Hermes home and refreshes profile `.env` files. An existing `OPENROUTER_API_KEY` in a profile `.env` is kept. Tokens live in `data/local-secrets.env`, which is gitignored. Do not commit that file.

## What an audit produces

Under `reports/<domain>-<timestamp>/`:

- `report.html` is the branded client report. The default brand colour is `#12a37f` and the default agency name is Spearmint.
- `pitch.md` is the one-page pitch.
- `issues.csv`, `pages.csv`, and `audit.json`.
- `fix-pack/` contains `redirects.htaccess`, `redirects.nginx.conf`, `vercel.json`, `robots.txt`, `llms.txt`, `organization.jsonld`, `yoast-titles.csv`, and `PLATFORMS.md` for WordPress, Shopify, Webflow, and Next.js.

PDF export uses Playwright and is skipped when Playwright is not installed. The HTML report can also be printed from a browser.

Tickets use these hours: critical 4, high 2, medium 1, low 0.5, plus 0.15 hour for each extra URL, capped at 3 extra hours. The pitch multiplies total hours by ₹1,000. Owners are content, seo, or developer. A later audit can be compared with `diff_audits` to show what was fixed.

The grade is A at 90 or above, B at 80, C at 70, D at 55, otherwise F. Critical findings weigh more than low ones, and a PageSpeed score is averaged into the performance score when a PageSpeed sample exists.

## Safety rules that must stay in place

- Crawl with at most 5 concurrent requests and the Spearmint user agent.
- Do not probe `/.git`, `/.env`, or admin paths. Security checks are passive: TLS, headers, cookies, and DNS email records.
- `submit_findings` requires evidence, a known severity, and a title, reason, and fix for any custom rule.
- QA rejects a finding that has no evidence id.
- `queue_delivery` only accepts an audit whose status is `done`. Nothing is sent to a client automatically.
- WordPress apply is limited to title rules and only runs after `python -m engine.wordpress approve <audit_id> --reviewer "Name"`. There is no MCP tool that grants that approval. The agent cannot approve itself.
- DataForSEO, Search Console, and GA4 return `available: false` until their environment variables are set. The off-page agent must say the data was not run. It must not estimate traffic.

## Secrets

These files are gitignored and must stay that way:

- `audit-agent/.env` holds `AUDIT_MCP_TOKEN`, `WEBHOOK_SECRET`, and optional API keys.
- `data/local-secrets.env` holds the A2A bearer tokens and the same engine token.
- `%LOCALAPPDATA%\hermes\profiles\<name>\.env` holds each agent's token, the engine token, and `OPENROUTER_API_KEY`.
- `data/audits.db`, `data/outbox/`, and `reports/` are local output.

`.env.example` and each profile `.env.example` contain placeholders only. Copy them and fill the values. The engine still runs when the optional keys are blank.

| Variable | Used for |
|---|---|
| `AUDIT_MCP_TOKEN` | MCP bearer token. Must match the profile `.env` files |
| `WEBHOOK_SECRET` | HMAC secret for `/webhooks/audit` |
| `OPENROUTER_API_KEY` | Hermes models. Not set in the handover build |
| `PAGESPEED_API_KEY` | Removes the shared PageSpeed quota. Without it the pipeline samples one URL and often receives HTTP 429 |
| `OPENAI_API_KEY` | Optional narrative summary via `--ai`. The HTML report has a template summary without it |
| `DATAFORSEO_LOGIN` and `DATAFORSEO_PASSWORD` | Off-page backlinks and ranked keywords. India location code 2356 |
| `SEARCH_CONSOLE_ACCESS_TOKEN` | Search Console queries |
| `GA4_ACCESS_TOKEN` | GA4 overview |
| `WP_USER` and `WP_APP_PASSWORD` | WordPress application password for approved title edits |
| `AUDIT_DOMAIN` | Hostname Caddy publishes for the lead A2A port |

## Production

`deploy/docker-compose.yml` runs three services on a Linux VPS: the audit engine with Chromium, the official `nousresearch/hermes-agent:stable` image, and Caddy. Hermes and Caddy use host networking so the A2A ports bind on the host. On Docker Desktop for Windows, skip Caddy and publish the engine port only.

Caddy publishes only port 9900. Specialist ports stay on localhost. Set `A2A_BEARER_TOKEN` and `A2A_PUBLIC_URL` before changing `A2A_HOST` away from `127.0.0.1`.

`deploy/install-profiles.sh` copies `hermes/profiles` into the container and starts each gateway. Nightly backup is `deploy/backup.sh` (or `backup.ps1` on Windows), keeping 14 days. `deploy/healthcheck.sh` curls the engine health endpoint and the lead agent card. Engine logs: `docker compose logs -f audit-engine`. Hermes token cost: `docker exec hermes hermes insights`. The engine itself makes no model calls.

Suggested host: 4 vCPU, 8–16 GB RAM, Mumbai region. Back up `~/.hermes` inside the container data volume and `data/`.


The fixture server plants known issues and asserts they are found, and that a short list of false alarms is absent. Every stored finding must have evidence. The phase-6 test asserts that DataForSEO, Search Console, GA4, and WordPress apply stay closed without keys and without an approval row.

## Known limits

- `OPENROUTER_API_KEY` is not filled in. Gateways will not complete a model turn until it is. `hermes -p <name> model` switches a profile to Nous Portal instead.
- Playwright browsers are not installed on the development PC. `--render`, `--axe`, and PDF export no-op or skip until `playwright install chromium`. The Docker image installs Chromium.
- PageSpeed without an API key is quota limited. Treat a missing lab score as "not measured", not as a passing grade.
- Pin `mcp` below version 2. Version 2 renamed FastMCP. Keep `sse-starlette` below 2.2 so it does not force a Starlette upgrade that breaks other local Python tools.
- FastMCP turns on DNS-rebinding protection for host `127.0.0.1`. A reverse proxy that sends a different Host header can be rejected.
- Hermes profiles on this PC were installed for the local user. A new machine needs `hermes/bootstrap.ps1` again. Do not copy profile `.env` files into git.
- The GitHub repository is private under the account `Krux-ai-official`.
